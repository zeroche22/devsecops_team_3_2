# Перевірка доступу до vSphere

Перевірено 14 листопада 2026 року через API vCenter під обліковим записом `y.manzhos@vsphere.local`.

Вхід успішний. Сервер — VMware vCenter Server 7.0.3. На папці `Datacenter/vm/Students-VMs/team-3` користувачу призначено роль `Student-ReadOnly` без поширення на дочірні об'єкти. Вона містить лише `System.Anonymous`, `System.Read`, `System.View`, `VirtualMachine.Interact.AnswerQuestion` і `VirtualMachine.Interact.ConsoleInteract`.

| Ресурс | Результат перевірки |
|---|---|
| `Students-VMs/team-3` | Папка доступна, VM та шаблони не відображаються |
| `Datacenter/host/192.168.5.100` | Об'єкт знайдено за шляхом, читання властивостей заборонено: `System.View` |
| `Datacenter/datastore/Toshiba_2TB` | Об'єкт знайдено, читання властивостей заборонено: `System.View` |
| `Datacenter/network/VM Network` | Об'єкт знайдено, читання властивостей заборонено: `System.View` |
| `Datacenter/vm/ubuntu_24.04.3` | Об'єкт знайдено, читання заборонено; він не є підтвердженим шаблоном Oracle Linux 9 |

У vCenter існує роль `STUDENTS-Terraform-Operator`, але поточному користувачу на перевірених ресурсах її не призначено. Розгортання VM з поточною роллю неможливе. Перевірка не змінювала VM, ролі або дозволи.

Для продовження потрібен обліковий запис з правами читання інфраструктури, клонування потрібного шаблону, створення та конфігурації VM у цільовій папці, виділення місця datastore, призначення мережі й resource pool. Доступ має охоплювати відповідні об'єкти та створювані VM; сама наявність ролі у списку ролей не надає цих прав.

Також потрібен шаблон Oracle Linux 9 або можливість підготувати його з ISO. Наявність такого шаблону не підтверджена через обмежену видимість.

Пароль збережено лише в локальному ігнорованому `terraform/terraform.tfvars` з правами `0600`. У Terraform перевірка TLS увімкнена за замовчуванням. Для API-аудиту лабораторного сервера використано TLS без перевірки CA; для постійного запуску слід налаштувати довірений CA.
