## Что выявлено при чтении исходника

- Terraform использует vSphere, но шаблон называется `ubuntu_24.04.3`; нужен подтверждённый шаблон Oracle Linux 9.
- Указаны старые IP `192.168.5.103–105`, имена `Study3-*` и параметры vCenter. Их нельзя считать свободными ресурсами нового проекта.
- Ansible использует `apt`, Ubuntu Docker repository, UFW, группу `sudo` и сервис `ssh`: требуется адаптация к Oracle Linux 9.
- В ролях записаны публичные SSH-ключи старого проекта; нужно заменить их параметрами нового inventory.
- Проверка SSH host keys отключена в inventory, Ansible config и deploy workflow; в рабочей версии нужны проверенные host keys.
- В исходном inventory 3 ВМ по 2 vCPU / 2 GiB; эти значения не подтверждают достаточность ресурсов для всего нового стека.
- В workflow имеются проверки контейнера, Trivy, SBOM, Grype, публикация GHCR, Cosign, release и deploy на Minikube. Terraform validate и ansible-lint присутствуют в pre-commit, но отсутствуют как отдельные проверки CI.
- Deploy привязан к старому runner, IP и образу `latest`; нужен deploy нового приложения по неизменяемому digest.
- `app/` и `k8s/`, на которые ссылаются исходные роли и workflow, отсутствуют в этой справочной копии. Запускать её отдельно нельзя.
- Zabbix, Fluent Bit/Loki, Falco, kube-state-metrics и Veeam ещё предстоит реализовать в новом проекте.

Исходные версии зависимостей сохранены для прослеживаемости; перед использованием проверяем совместимость и фиксируем выбранные версии.
